# Ручной live QA: product lifecycle, этапы 1-12

Дата: 2026-07-11
Область проверки: доработки CRM по жизненному циклу товара, без этапа 13 "Казпатент".
Цель: пройти один товар вручную по всем ролям и убедиться, что UI, статусы, права, история и KPI работают как задумано.

---

## 0. Подготовка

### Доступы

Используй эти тестовые аккаунты, если они уже есть в системе:

| Роль | Email | Пароль | Что проверяет |
| --- | --- | --- | --- |
| Администратор | `admin@example.com` | `admin123` | создание товара, назначение дизайнера, проверка, доработка, approve, история, KPI |
| Дизайнер | `qa_designer@example.com` | `qa123456` | материалы, карточка создана, повторная отправка после доработки |
| Менеджер маркетплейса | `qa_marketplace@example.com` | `qa123456` | Kaspi, запуск продаж, редактирование параметров продаж |
| Закупщик | `qa_purchase@example.com` | `qa123456` | первичный закуп, поступление товара |
| Склад | `qa_warehouse@example.com` | `qa123456` | складской паспорт |

Если какого-то QA-пользователя нет:

- зайди под админом;
- открой `Пользователи`;
- создай пользователя с нужной ролью и паролем `qa123456`.

### Тестовый товар

Создай уникальное имя товара, чтобы не смешивать проверку со старыми QA-записями:

```text
Manual QA Lifecycle 2026-07-11 <твои инициалы или время>
```

Пример:

```text
Manual QA Lifecycle 2026-07-11 1530
```

Дальше в инструкции `ТЕСТОВЫЙ_ТОВАР` означает именно это имя.

### Файл для загрузки

Подготовь любой небольшой файл:

- для материала дизайнера: PNG/JPG, например картинка товара;
- для доработки: можно тот же PNG/JPG или любой PDF.

Если тестируешь локально из проекта, можно взять:

```text
client/public/logo192.png
```

### Как фиксировать результат

На каждом шаге отмечай:

- товар найден в нужной очереди;
- кнопка действия соответствует текущему этапу;
- после сохранения модалка закрывается или данные обновляются;
- статус товара меняется на ожидаемый;
- нет явных визуальных проблем: наложения текста, сломанных кнопок, пустых блоков, бесконечных загрузок.

- [ ] Найди `ТЕСТОВЫЙ_ТОВАР`.

Ожидаемо в timeline:

- создание товара;
- привязка поставщика;
- назначение дизайнера;
- загрузка материала;
- карточка создана;
- передача на проверку;
- отправка на доработку;
- повторная отправка после доработки;
- approve;
- обновление маркетплейса;
- передача в закуп;

## 16. Быстрые проверки прав по ролям

Не обязательно проходить все, но полезно посмотреть 2-3 пункта.

### Дизайнер

- [ ] Видит в `Очередь` только свои дизайнерские задачи.
- [ ] Может загрузить материалы.
- [ ] Может отправить на проверку.
- [ ] Не видит approve как доступное действие.
- [ ] Не должен управлять Kaspi, закупом и складом.

### Marketplace manager

- [ ] Видит маркетплейс-задачи.
- [ ] Может заполнить Kaspi.

- [ ] Не должен оформлять закуп.

- [ ] Видит задачи закупа.
- [ ] Может оформить закуп и поступление.

### Warehouse operator

- [ ] Видит складские задачи.
- [ ] Может заполнить складской паспорт.
- [ ] Не должен редактировать Kaspi.
- [ ] Не должен approve-ить карточку.

### Admin

- [ ] Видит общую очередь.
- [ ] Может фильтровать по этапу, дизайнеру и ответственному.
- [ ] Видит историю товара.
- [ ] Видит KPI дизайнеров.

## 18. Если что-то пошло не так

Запиши в свободной форме:

```text
Шаг:
Роль:
Товар:
Что нажал:
Что ожидал:
Что произошло:
Скриншот:
```

Типичные сигналы реального бага:

- статус не изменился после успешного действия;
- товар пропал из всех очередей;
- действие доступно не той роли;
- сохраненные поля исчезли после обновления страницы;
- история не показывает ключевое событие;
- KPI не появился после approve;
- модалка зависла в loading;
- кнопка активна, но ничего не делает;
- текст/кнопки перекрываются или форма неудобна для заполнения.

Типичные не-баги:

- товар исчез из очереди текущей роли после передачи дальше, потому что он перешел к другой роли;
- после складского этапа товар уже `В продаже`, но запуск продаж еще нужно завершить маркетплейсу;
- частичное поступление `4/5` нормально: остаток должен стать `4`, а не `5`.
