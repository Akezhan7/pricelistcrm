# Исправления Этапа 4 - Финансовый модуль (дебиторка)

## Проблемы которые были исправлены:

### 1. 429 (Too Many Requests) - Rate Limiting
**Проблема:** Слишком строгие ограничения rate limiter (100 запросов за 15 минут)
**Решение:** Увеличили лимиты до 1000 запросов за 1 минуту для разработки

### 2. Платежи не сохранялись в истории
**Проблема:** При оплате заказа через `updatePayment` в orderController создавалась только запись в OrderStatusHistory, но не в таблице Payment
**Решение:** Добавили создание записи Payment при каждой оплате заказа

### 3. UI не обновлялся после платежей
**Проблема:** После добавления платежа интерфейс не обновлялся корректно
**Решение:** Добавили вызов `onSuccess()` и `onRefresh()` для перезагрузки данных

### 4. Отсутствие истории платежей по заказу
**Проблема:** Не было возможности посмотреть все платежи по конкретному заказу
**Решение:** Добавили новый API endpoint `GET /api/orders/:id/payments` и соответствующий метод в ordersApi

## Архитектура финансового модуля:

### Модели и связи:
- **Payment** - основная таблица платежей
- **Order** - поля `totalAmount`, `paidAmount`, `paymentStatus`
- **Supplier** - поле `debt` (автоматически пересчитывается)

### API Endpoints:
- `GET /api/payments` - все платежи с фильтрацией
- `GET /api/payments/supplier/:supplierId` - платежи и долги конкретного поставщика
- `POST /api/payments` - создание платежа
- `PUT /api/payments/:id` - обновление платежа
- `DELETE /api/payments/:id` - удаление платежа
- `PATCH /api/orders/:id/payment` - быстрая оплата заказа
- `GET /api/orders/:id/payments` - история платежей по заказу

### UI компоненты:
- **SupplierFinanceModal** - управление финансами поставщика
- **PaymentModal** - оплата конкретного заказа
- **Финансовый блок в SupplierCards** - отображение задолженности

## Бизнес-логика:

### Автоматические расчеты:
1. При создании заказа - добавляется к задолженности поставщика
2. При оплате через Payment API - автоматическое распределение по заказам
3. При оплате через Order API - создание записи Payment
4. При удалении/изменении - пересчет всей задолженности

### Статусы оплаты заказов:
- **"Не оплачено"** - paidAmount = 0
- **"Частично оплачено"** - 0 < paidAmount < totalAmount  
- **"Оплачено"** - paidAmount >= totalAmount

### Распределение платежей:
- Если указаны конкретные заказы - оплачиваются они
- Если не указаны - автоматическое распределение по старым заказам (FIFO)
