# 🔐 SECURITY CHECKLIST - Проверьте перед деплоем!

## ⚠️ КРИТИЧЕСКИ ВАЖНО

### 1. JWT_SECRET
- ❌ **НЕ используйте:** `your-super-secret-jwt-key-here-change-in-production`
- ✅ **Сгенерируйте новый:**
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
- **Минимум:** 32 символа
- **Должен быть:** случайным и уникальным

### 2. Пароль администратора
- ❌ **НЕ используйте:** `admin123`
- ✅ **Используйте сильный пароль:**
  - Минимум 12 символов
  - Буквы верхнего и нижнего регистра
  - Цифры и спецсимволы
  - Пример: `Adm!n2025$SecurePass`

### 3. Пароль базы данных
- ❌ **НЕ используйте:** `postgres`, `password`, `123456`
- ✅ **Сгенерируйте сильный пароль** или используйте пароль от хостинга

### 4. NODE_ENV
- ✅ **В production ОБЯЗАТЕЛЬНО:** `NODE_ENV=production`
- Это включает:
  - Строгий rate limiting
  - Отключение CORS для dev доменов
  - Проверку JWT_SECRET
  - Оптимизацию производительности

### 5. CLIENT_URL
- ❌ **НЕ оставляйте:** `http://localhost:3000`
- ✅ **Укажите точный домен фронтенда:** `https://your-frontend-domain.com`
- **БЕЗ слеша** в конце!

---

## 🛡️ РЕКОМЕНДУЕТСЯ

### 6. HTTPS
- ✅ Всегда используйте HTTPS в production
- Railway, Render, Vercel предоставляют автоматически

### 7. Переменные окружения
- ❌ **НЕ коммитьте** `.env` файлы в Git
- ✅ Проверьте что `.env` в `.gitignore`
- ✅ Используйте `.env.example` для документации

### 8. Регулярные обновления
```bash
# Проверка уязвимостей
npm audit

# Автоматическое исправление
npm audit fix

# Обновление зависимостей
npm update
```

### 9. Ограничение прав БД
- ✅ Создайте отдельного пользователя для приложения
- ❌ НЕ используйте суперпользователя `postgres` в production

### 10. Бэкапы базы данных
- ✅ Настройте автоматические бэкапы
- Railway и Render делают это автоматически
- Проверяйте возможность восстановления

## ⚡ ДОПОЛНИТЕЛЬНО

### 11. Rate Limiting
Уже настроено:
- 100 запросов за 15 минут (production)
- 5 попыток входа за 15 минут

### 12. CORS
Уже настроено:
- Whitelist только указанных доменов
- Проверка origin в production

### 13. SQL Injection Protection
✅ Защищено через Sequelize ORM (параметризованные запросы)

### 14. XSS Protection
✅ Helmet middleware включён

### 15. Мониторинг
Рекомендуется добавить:
- **Sentry.io** - отслеживание ошибок
- **LogRocket** - мониторинг фронтенда
- **UptimeRobot** - проверка доступности

## 📋 БЫСТРЫЙ ЧЕКЛИСТ

Перед деплоем убедитесь:

```
[ ] JWT_SECRET сгенерирован (32+ символа)
[ ] DEFAULT_ADMIN_PASSWORD изменён на сильный
[ ] DB_PASSWORD не является стандартным
[ ] NODE_ENV=production в production
[ ] CLIENT_URL указывает на production домен
[ ] .env файлы НЕ в Git репозитории
[ ] npm audit не показывает критических уязвимостей
[ ] HTTPS включён (автоматически на хостингах)
[ ] Настроены бэкапы БД
[ ] Health check (/health) возвращает 200
```

## 🚨 ЧТО ДЕЛАТЬ ЕСЛИ СКОМПРОМЕТИРОВАН JWT_SECRET?

1. **НЕМЕДЛЕННО** сгенерируйте новый ключ
2. Обновите переменную `JWT_SECRET` на сервере
3. Перезапустите сервер
4. Все пользователи будут разлогинены (нормально)
5. Оповестите пользователей о необходимости перелогиниться
